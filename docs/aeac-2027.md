# AEAC 2027 competition integration

This document specifies the AEAC 2027 competition-specific integration for
NOMAD. It is subordinate to the [PRD](prd.md) and
[architecture](architecture.md): organizer requirements come from the CONOPS
inventory, while this document owns the external-server contract and the
competition module boundary.

The reusable NOMAD core must remain competition-agnostic. AEAC-specific wire
formats, credentials, cadence rules, scoring diagnostics and traffic translation
belong in an opt-in competition module, not in vehicle, mission, safety or
MAVLink implementation code.

## Official source and current portal status

Official competition portal:
<https://aeac.mylonics.com/#/>

The supplied CONOPS states that the competition connection token and server
documentation are provided through the named competition portal
(AE27-NET-001). The portal responds as **AEAC Student Competition Server**, but
its documentation is rendered client-side; the available text-only retrieval in
this review did not expose the interactive connection instructions or wire
schema. The official wire schema and token lifecycle remain unimplemented (Q04).

Therefore the sections below intentionally separate source-confirmed behavior
from portal details that still need to be transcribed and tested. Do not infer an
HTTP, WebSocket, MQTT, JSON, protobuf or other transport merely from the portal
being a web application.

## Confirmed competition behavior

The following is source-confirmed from CONOPS v1.0 and is independent of the
portal's eventual wire encoding.

### Ownship telemetry

While the Task 1 UAV is armed, NOMAD must send competition telemetry at 1 Hz.
The logical payload contains:

| Logical field | Required semantics |
|---|---|
| UAV identifier | Bidder-defined string identifier |
| Timestamp | Unix timestamp; exact wire unit remains Q04 |
| Latitude | Decimal degrees |
| Longitude | Decimal degrees |
| Altitude | AGL metres |
| Horizontal accuracy | Metres |
| Vertical accuracy | Metres |
| Battery | Percentage, 0 through 100 |
| Mode | `off`, `idle`, `link-lost`, `failsafe`, `armed-pilot`, or `armed-automatic` |
| RC link quality | Bidder-defined normalized float from 0 through 1, with 1 best |
| Telemetry link quality | Bidder-defined normalized float from 0 through 1, with 1 best |

The core owns the source value, validity and age of those measurements. The AEAC
module owns mapping them into the official wire schema. Home-relative or MSL
altitude must not be labelled AGL without the reviewed conversion. GPS fix type
or satellite count must not be substituted for horizontal/vertical accuracy.

Relevant scoring behavior must also be reproducible in tests: at least 300 s of
armed telemetry is the positive baseline; missing telemetry begins a disconnect
penalty at 30 s and continues at 15 s intervals; packet spacing greater than
1.1 s or less than 0.4 s is penalized; startup while already armed and invalid
GPS while armed are penalized. The CONOPS latency wording is ambiguous and
remains Q04 rather than an implementation rule.

### Traffic feed

The competition server supplies flying-UAV traffic, including simulated UAVs,
at 1 Hz. NOMAD must react to the traffic and keep its own UAV outside each other
UAV's cylindrical radial and vertical exclusion zone.

The competition module translates server-native traffic records into generic
NOMAD traffic observations. The reusable core owns freshness policy,
deconfliction, mission consequences and operator advisories. A missing or stale
traffic feed means traffic state is unknown, never clear.

Exact traffic field names, altitude datum, cylinder radius/vertical semantics,
sequence/timestamp behavior, velocity availability, equality at a boundary,
freshness and right-of-way remain Q04 until the portal/organizers define them.

## Implementation boundary

The adapter must own competition schemas, credentials, telemetry cadence, traffic
translation and scoring diagnostics. It may submit only supported typed runtime
requests and must not own vehicle policy. No generic plugin framework is required.
Before implementation, capture and version the official portal contract, then use
isolated fixtures for malformed/stale tracks, outages, duplicate/replayed messages,
clock error, reconnect and credential expiry. Traffic separation, physical payload
outcomes and a complete Task 1/2 flight remain separate qualification gates.
